# jupjupalarm.com 사이트 (⑦ SEO 발행 담당용)

정적 사이트. `python3 site/build.py` → `site/public/` → Cloudflare Pages가 그대로 배포 (빌드 명령 없음, 출력 폴더 `site/public`, 감시 경로 `site/**`).

## 매일 하는 일 (⑦)
1. `git pull --rebase origin main`
2. '청약홈API' 탭 전체를 `site/data/applyhome.json`의 `rows`로 덮어쓰기 (열 이름 = 시트 머리글, `fetched_at` = A열 값).
3. 새 공고마다 `site/data/apt/{주택관리번호}.json` 작성 — 형식은 기존 파일 참고. 사실은 '청약조사' 탭·청약홈API 값만.
   - 필수: `title, kind, region{sido,sigungu}, take(한마디 2줄+), who, eligibility(행 배열), faq(3개+), account`
   - `aliases`: '청약조사' C열 단지명과 '오늘의 발행 플랜' C열 단지명이 title과 다르면 넣는다 (시트 스크립트가 스레드 링크·DM에서 이 이름으로 페이지를 찾음 — `public/links.json`).
   - 선택: `photo{image,credit,alt,pos}`(AA·X열), `map`(Y열), `coords`(Z열 [경도,위도]), `plans[{type,image,alt}]`(AC열 — 반드시 이미지를 열어 타입 확인), `areas`, `gap`(H열에 근거 단지가 있을 때만 — 아래 '비교 단지 시세'), `schedule`(자동 일정이 틀릴 때), `info_extra`, `sources_extra`, `related_extra`
   - 문장 속 날짜는 `{d:2026-11-02}` · `{r:2026-11-02:2026-11-03}`로 쓰면 '11.2(월)' 형식으로 바뀜.
   - 확인 못 한 자격은 `["항목", "공고문 기준 적용", "공고문 확인"]`.
   - 한마디·FAQ는 공고마다 새로 쓴다(템플릿 문장 돌려쓰기 금지). 차익은 근거 단지가 있을 때만 '약 O억 저렴(추정)'.
4. 시·군·구가 `site/data/regions.json`에 없으면 로마자 슬러그를 추가 (한 번 정하면 안 바꿈).
5. `python3 site/build.py` — 종료 코드 1이면 푸시하지 말고 `site/build-report.json`의 errors를 보고.
6. `git add site && git commit -m "site: 새 N · 고침 N" && git push origin HEAD:main`

## 임대·공고 전·배치도 (2026-10-28 추가)
- **임대** (LH공고·마이홈공고 탭): 파일 이름·key = `lh{공고ID}` (LH공고 D열) 또는 `mh{공고ID}-{주택순번}` (마이홈 공고ID). `"kind": "rental"`, `"source": "lh"`, `"source_name": "LH청약플러스"`, `source_url`(공식 공고), `rcpt`, `announce`, `notice_date`, `schedule`(직접), `rent_models`[{type, target, excl, supply_area, units, deposit, monthly}] — 금액이 '공고문 참조'면 deposit·monthly 빼기. `rent_summary`{deposit, monthly, basis}는 마이홈 대표 조건(임대보증금·월임대료 열)일 때 basis에 "마이홈 대표 조건 · 주택형별 상이". 예시: `lh0000061190.json`(금액 있음), `lh2015122300020925.json`(계층별·금액 공고문 참조).
- **매입임대(여러 동네 다가구·다세대를 한 공고로 모집)** (2026-10-29 추가 — 사용자 요청 "임대 공고는 검색량이 많아 알차게"): 예시 `lh2015122300020945.json`. 만든다.
  - `houses`: 'LH공고' L열의 `[공급] 호: … · 주소: …` 줄을 파일로 저장해 `python3 site/tools/lh_houses.py L열.txt --into site/data/apt/{key}.json`으로 넣는다 (손으로 옮겨 적지 않기). 지역별·면적별 막대, 지역 거르기, 주택 목록(동·이름·도로명·호·층·㎡·평)이 자동으로 나온다. 목록이 잘려 있으면(셀 길이 한계) 있는 만큼 넣고 `units`에 공고의 전체 호수, `units_note`에 "목록은 일부 · 전체는 공고 첨부"를 쓴다.
  - `rental_type`: "일반 매입임대" / "청년 매입임대" / "신혼·신생아 매입임대" / "다자녀 매입임대" / "든든전세" (임대 조건 위 설명 문장이 붙음). `rent_level`(예 "시중임대료 30% 수준" — LH 공고 임대조건 그대로), `rent_range` {deposit:[최저,최고], monthly:[최저,최고], basis} — '청약조사' G열에 공급대상주택목록 기준 범위가 있을 때만, `lease`(임대기간), `steps`([[제목, 설명]] 신청 방법 3~5단계 — 주택 열람·방문/인터넷 접수·발표·계약, 공고에 있는 사실만), `receipt_note`(방문 접수·시간).
  - `region`은 대표 시·도(호수가 많은 쪽), sigungu는 "". 다른 시·도 주택도 있으면 그 지역 목록에도 자동으로 나온다. 제목은 "LH 매입임대 {지역}·{지역} N호"처럼 검색어(LH 매입임대 월 2,330회)가 앞에 오게. `search_names`에 "{지역} 매입임대"들을 넣는다.
  - 자격(순위·소득·자산)은 '청약조사' I열 그대로, 모르면 "공고문 확인". 집별 보증금·월세는 목록에 없으면 쓰지 않는다 (범위만).
  - 전세임대(LH가 집을 사지 않고 입주자가 직접 구한 집을 전세 지원)는 주택 목록이 없으니 `houses` 없이 자격·지원 한도·일정·신청 방법(`steps`) 중심으로 만든다.
- **공고 전** (수도권, '청약조사'에서 청약홈 공고가 아직 없는 분양 단지): key = `pre-{영문 슬러그}`, `"pre": true`, 모든 값 보도 기준. `rcpt`(예정 접수일), `price_text`·`price_short`, `pre_rows`, `schedule`(note "예정 · 보도 기준"), `source_line`, `sources_extra` 필수. 예시: `pre-the-h-banpo-124.json`.
  - 공고가 나오면 새 공고 파일을 만들고, pre 파일에 `"moved_to": "{주택관리번호}"`를 추가한다. pre 페이지는 **지우지도 옮기지도 않는다** (사용자 결정 2026-10-28 — 이미 검색 상위에 있을 수 있음). 빌드가 자동으로: 배지 '공고 나옴', 제목 위 파란 CTA '공식 공고가 나왔어요 → 확정 분양가·청약 일정 보기', '예상과 실제 비교' 표(분양가·접수 시작·공급), 제목을 '… 예상 vs 실제 분양가 — 공고 전 전망 정리'로 바꾸고, 새 공고 페이지 출처에 이 페이지 링크를 단다. 목록에서는 빠지고 사이트맵에는 남는다.
  - 이때 pre 파일의 take·who·faq를 '공고 전 예상은 …였고 실제 공고는 …' 식의 비교·회고 문장으로 고쳐 쓴다 (새 공고 페이지와 같은 문장을 쓰지 않기 — 검색어가 겹치지 않게 이 페이지는 '예상·전망·비교'에 집중).
- **배치도·동호배치도**: '청약조사' AE·AG열 파일을 반드시 Read로 열어 확인한 뒤 `"layouts": [{"kind": "배치도", "image": "photos/layout-….jpg", "alt": "…"}]` (동호배치도는 kind "동호배치도"). 출처는 `image_credit_owner`. 공고당 이미지(조감도·평면도·배치도 합계) 최대 6장.

## 비교 단지 시세 (2026-10-29 사용자 결정 — "모든 공고, 임대주택은 비교단지 시세 확보")
- **모든 공고**에 `gap`을 채우는 것이 기본이다. ① 조사 담당이 '청약조사' H열에 근거 단지와 함께 적어 두고, 이 페이지는 H열 값 그대로 옮긴다 (H열이 "확인필요"·"해당없음"이면 `gap` 없이).
- 분양(줍줍·공공분양·민간·신혼희망타운): `verdict` "약 O억O천만원 저렴(추정)" 또는 "차익 기대 낮음(추정)", `rows` 첫 줄 = ["{비교 단지} {면적}㎡ 실거래 (YYYY.MM)", "O억O천만원"], 둘째 줄 = 이 단지 같은 면적 분양가. 토지임대부는 "건물분양가 기준 약 O억 저렴(추정)" + 월 토지임대료 줄.
- 임대(행복주택·국민임대·매입임대·장기전세 등 — 전세임대는 집이 정해져 있지 않아 제외): 같은 동네·비슷한 면적의 **전월세 실거래**와 비교한다. `verdict`는 셋 중 하나로 — "월세 약 O만원 저렴(추정)" / "보증금 약 O천만원 저렴(추정)"(전세형) / "주변 시세의 약 O% 수준(추정)". `rows` 첫 줄 = ["{비교 단지} {면적}㎡ 월세 실거래 (YYYY.MM)", "보증금 O만원 · 월 O만원"], 둘째 줄 = 이 공고 같은 면적 보증금·월세. 공고문에 '시중시세의 O% 수준'이 있으면 그 문장을 `rent_level`에 그대로 쓰고, 비교 단지는 따로 붙인다.
  - 보증금·월세가 둘 다 다르면 공고의 전환율로 섞어 계산하지 말고, 같은 보증금 수준의 거래를 찾거나 % 수준으로 쓴다 (계산 근거를 `text`에 한 문장).
  - 매입임대처럼 여러 동네면 호수가 가장 많은 동네 1곳 기준으로 쓰고 `text`에 그 동네를 밝힌다.
- 근거: 국토교통부 실거래가 공개시스템(rt.molit.go.kr) 값을 인용한 공식 자료·기사 우선. 기사 값이면 `basis`에 "실거래는 기사 기준". 블로그·부동산 앱 시세는 쓰지 않는다. 근거 단지가 없으면 숫자를 만들지 않는다.
- 공유 썸네일 (2026-10-29 사용자 결정 "핵심만, 후킹 메시지만"): 큰 두 줄 + 칩 하나만, 작은 설명 줄은 없다. 윗줄 = 어디·무엇(예 '과천시 무순위 줍줍', '인천 부평구 행복주택'), 아랫줄 = 훅 하나 — 비교 시세가 있으면 '시세보다 약 O 저렴'(임대 '주변 시세보다 …'), 없으면 '분양가 O억'('최고' 빼기)·'84㎡ 5억대'·'월 O만원대 · 보증금 O천만원대'(내림 + '대'). 발표 대기·완료는 '{단지명}' / '경쟁률 O.O대 1'. 칩은 급한 정도(D-n·D-n 마감·오늘 마감·하루만 접수·날짜 접수). 비교 단지·(추정) 같은 근거는 썸네일에 쓰지 않고 공고 페이지 '시세와 비교하면'에 둔다 (훅엔 꼬리표 없이 — SNS ③ 규칙과 같음). 토지임대부·'차익 기대 낮음'은 시세 훅으로 쓰지 않는다.

## 판단형 블록 `decide` (2026-10-29 사용자 결정 — "넣는 게 이득인지 판단할 수 있게", 시범: 2026930043)
접수 중·예정인 분양·줍줍·공공분양·신혼희망타운 공고에 넣는다 (임대는 아래 '임대 판단 카드'). 있으면 페이지 맨 위에 '3초 판단' 카드, 그 아래 이런 분께 → 시세 막대 → 돈 흐름(계산기) → 최근 줍줍 경쟁률(무순위만, 자동) → 다만 → 30초 체크가 붙는다. 예시: `2026930043.json`의 `decide`.
- 자동으로 채워지는 칸: 이득(gap 첫 줄 시세·둘째 줄 분양가에서 % 계산 — gap이 없으면 '비교 시세 확인 중'), 경쟁(공급 세대 수·하루 접수·최근 45일 수도권 줍줍 경쟁률 가운데값), 자금(최고 분양가 × `funds.deposit_pct`).
- 네가 쓰는 칸 (모두 공고문·청약홈·'청약조사' I·G열·기사에 있는 사실만, 기사 값은 '(기사 기준)'):
  - `door` {sig, head, sub}: 신청 문턱. sig = 청약통장·소득·거주지역 조건이 없으면 "g", 하나면 "y", 둘 이상이면 "r" (무주택은 셈하지 않음). head 15자 안팎 (예 "과천 거주 무주택 세대주만", "통장 없이 무주택이면 누구나").
  - `fit` {yes: [[누구, 왜]] 2~3개, no: [[누구, 왜]] 2~3개}: '왜'는 그 공고의 조건(거주지역·거주의무·계약금·전매·재당첨)에서만. 수익·시세 상승 전망 금지.
  - `funds` {deposit_pct, card_tail(예 "실거주 5년"), price_options [[동·타입, 원]](동·타입별 가격이 공식·기사에 있을 때만, 없으면 빼면 최고가 하나), steps [[이름, 시점(날짜는 {d:…}), %]] — 계약금·중도금·잔금 비율이 확인된 것만 (모르면 funds 전체를 뺀다), basis(출처 한 문장), note(입주까지 기간·중도금 대출 확인 등 한두 문장)}.
  - `traps` [[제목, 한 문장]] 3~4개: 하루 접수·거주의무·전매 제한·재당첨 제한·계약금 단기 납부·방문 계약 등.
  - `check` {title, items 4~5개(그 공고의 실제 자격·자금 조건을 '예/아니오' 문장으로), result("모두 '예'면 … 조건을 갖춘 거예요. 세부 기준은 입주자모집공고로 확인하세요." — '넣으세요' 같은 권유 금지)}.
  - `comp_note`(무순위만): 이 공고의 세대 수·대상 조건 한 문장 + "예측이 아니라 참고용" 한 문장.
- **임대 판단 카드** (2026-10-29 시범: `lh2015122300020958` 화성 동탄 행복주택): 임대 공고도 접수 중·예정이면 `decide`를 넣는다. 칸이 다르다 — 월 부담(자동: rent_models·rent_summary 월세 범위 + gap 또는 `rent_level`로 신호, 비교 전이면 회색) · 문턱(`door`, sig = 무주택·계층 자격 말고 소득·자산 기준과 거주지역 제한이 없으면 g, 하나면 y, 둘이면 r) · 거주기간(`stay` {sig, head, sub}, 최장 10년 이상 g · 4~9년 y · 그 밖 r — 행복주택은 시행규칙 별표 5: 대학생·청년 10년, 신혼·한부모 10년(미성년 자녀 14년), 고령자·주거급여 20년; 다른 유형은 공고문 임대기간) · 입주 돈(자동: 보증금 범위, 1억↑ r · 3천만↑ y). 그 아래 '입주할 때·매달 나가는 돈'(블록·주택형별 보증금·월세·2년 합계 + 보증금 계산기)이 rent_models 금액으로 자동으로 나온다. `conv` {up, down, unit}은 공고·LH 안내에 전환이율이 있을 때만 (보증금↔월세 바꾸기 계산), `rent_basis`·`rent_note`·`links`[[굵은 글, 주소, 설명]](발행된 가이드만 — 없는 주소면 빌드 오류), `fit`·`traps`·`check`는 분양과 같다.
- 신호색 기준은 페이지에 그대로 공개된다 — 기준을 바꾸려면 build.py `make_decide`를 고친다 (사람이 정한 기준이라 ⑦은 바꾸지 않음).

## 국토교통부 실거래가 API (2026-10-29 연결 — 비교 단지 시세의 1차 출처)

## 검색 키워드 (2026-10-29 추가 — 청약노트 블로그와 같은 네이버 API)
- 키: 구글 시트 '청약노트 블로그 운영'(id 1B20bC25MYQl5uHGCFx6_QQp2G_7AEJ-rTPTSbrM9d4E) '키' 탭 B2:B6 (NAVER_CLIENT_ID, NAVER_CLIENT_SECRET, SEARCHAD_API_KEY, SEARCHAD_SECRET_KEY, SEARCHAD_CUSTOMER_ID). 세션 임시 폴더에 `KEY=VALUE` 파일(권한 600)로 만들어 `CHEONGYAK_ENV=그 경로`로 넘긴다. **값을 출력·커밋하지 않는다.** 끝나면 파일을 지운다.
- `python3 site/tools/keywords.py` → 키워드 파일이 없거나 7일 지난 공고만 조회해 `site/data/keywords/{key}.json`(월간 검색량 PC·모바일, 상위 8개는 블로그 문서 수, 단지명이 들어간 연관 키워드). 새 공고·고친 공고는 `python3 site/tools/keywords.py {key} …`로 바로 조회. 목록용 일반 키워드는 `--site`(월 1회).
- 빌드가 자동으로 쓰는 곳: ① 제목 단어 — 페이지에 실제로 있는 주제(분양가·청약 일정·평면도·경쟁률·줍줍·보증금·월세 …) 중 검색량 많은 2개 (발표 후엔 경쟁률 고정, 무순위는 줍줍 검색이 많으면 '무순위(줍줍)') ② 설명 끝 문장 ③ 검색량 50 이상 주제의 소제목 앞에 단지명 (최대 3개).
- `site/build-report.json`의 `seo_gaps` = 검색은 많은데(월 100+) 페이지에 없는 주제 (예: '고덕강일3단지 모델하우스 (2,020)'). 시트·공고문에 사실이 있으면 FAQ나 본문에 채우고, 없으면 그대로 둔다 (지어내지 않기). 모델하우스 위치는 공고문·공식 홈페이지에 있을 때만 `model_house` {"address": "…", "note": "…"}로 넣고 FAQ에 쓴다.
- FAQ 질문은 검색량 상위 롱테일 키워드의 말투로 쓴다 (예: '충정로역자이르네 줍줍 자격은?'). 검색량이 단지명 줄임말 쪽이 크면(`names`) `aliases`·`search_names`에 넣는다.
- 단지명 변형이 자동으로 안 잡히면(블록 번호 가운데 등) apt 파일에 `"search_names": ["시흥하중 신혼희망타운"]`을 넣고 다시 조회.
