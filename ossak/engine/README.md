# 오싹알람 제작 엔진 (클라우드용)

오싹알람(@ossak_alarm) 인스타툰 한 편을 콘티 → 그림 → 조판 → 발행 준비까지 만드는 도구.
매일 클라우드 예약 작업 '오싹알람 새 편 제작'이 이 문서대로 한 편을 만든다.

## 구성
- `ossak/mk.py` story.json → episode.json (컷 ID·크기·말머리 색 자동)
- `ossak/cf.py` Cloudflare Workers AI FLUX.2 klein(무료)으로 컷 생성. 키는 환경변수 `CF_ACCOUNT_ID`, `CF_API_TOKEN`
- `ossak/compose.py` 1080×1350 조판 → `slides/NN.png`
- `ossak/finish.py` 저장소 `ossak/<편>/NN.jpg` 생성, `preview.jpg`, 발행계획 행 `rows.json`
- `ossak/render.py`, `ossak/batch.py` Gemini(유료) — 사용자가 승인했을 때만
- `fonts/` 고운바탕·개구·Noto Sans KR(OFL), `refs/boogi_sheet.png` 부기 캐릭터 시트
- `episodes/<ID>-<slug>/` story.json·episode.json (그림·슬라이드 PNG는 커밋하지 않음)

## 하루 한 편 만들기
1. 시트 '설정' B15·B16 값을 읽어 `export CF_ACCOUNT_ID=… CF_API_TOKEN=…`, B17(구글 TTS 키)이 있으면 `export GOOGLE_TTS_KEY=…` (값을 출력하지 않는다).
2. 소재 고르기: '소재조사'에서 상태 '조사중' 중 '조사노트' 사실이 충분하고 훅·핵심 사실이 A/B인 것 가운데 점수(M열)가 가장 높은 것 1개.
   화제 신호(L열)에 시의성(기념일·새 뉴스·다큐 공개)이 있으면 그 날짜에 맞춰 발행일을 앞당길 수 있다.
   말머리 비중(세계기담30·새벽괴담30·미제파일20·그날의 기록15·그 후5)과 최근 발행계획의 말머리가 겹치지 않게 고른다.
   '지침로그' 최근 행의 방향을 반영한다.
3. **PD 기획** — 작가(콘티)와 다른 에이전트가 PD를 맡는다. 조사노트 사실과 채널 컨셉(프로젝트 설명)만 보고 `episodes/<편>/brief.md`를 쓴다. 작가는 이 기획서대로 콘티를 쓰고, 마지막에 PD가 통과 여부를 정한다.
   기획서 항목 (각 1~3줄):
   - **로그라인**: "이 편은 ___한 이야기다" 한 문장. 친구에게 이 편을 한 문장으로 전할 말이기도 하다.
   - **시청자 진입점**: 왜 잠들기 전에 이걸 끝까지 넘겨 볼까. "내가 그 자리에 있었다면" 하고 느낄 지점 1개.
   - **콘티 유형** (사건 성격에 맞는 하나):
     - A 빈 현장형: 사람이 사라진 현장 → 거꾸로 추적 → 답. (디아틀로프, 메리 셀레스트, 플래넌)
     - B 목격담 조각형: 여러 증언 조각 → 하나의 정체. (조선 1609)
     - C 단서 추적형: 단서를 하나씩 따라가 신원이나 정체에 닿음. (서머턴)
     - D 확산형: 작은 시작 → 걷잡을 수 없이 커짐 → 뜻밖의 끝. (스트라스부르)
     - E 한순간 해부형: 72초나 7분 같은 짧은 순간을 장마다 쪼갬. (Wow)
     - F 썰형: 화제가 된 경험담이나 사연. 인스타는 존댓말 내레이션 유지.
   - **이해 체크포인트**: 3장까지 누가·언제·어디서·무엇을 / 7장까지 중심 질문 / 마지막 3장에서 답. 장마다 생각 하나.
   - **이름·용어**: 독자가 기억할 이름은 최대 2개. 낯선 말(감사, 육분의, 화구, 초저주파 등)은 처음 나오는 장에서 쉬운 말로 풀거나 아예 빼기.
   - **감정 곡선**: 장별 긴장도 1~5. 3 이하인 장이 2장 넘게 이어지지 않게.
   - **대표 그림 1장**: 이 편을 떠올리면 생각날 장면. 표지와 릴스 첫 프레임 후보.
   - **빼는 것**: 재미있지만 중심 질문과 무관한 사실 목록.
   - **답이 회수할 의문**: 본문에 던진 의문마다 답에서 회수하는지, 열린 의문으로 남기는지 표시. 회수도 안 하고 열린 의문도 아니면 본문에서 뺀다.
   - **채널 적합성**: 잠들기 전 1분 톤(차분하고 기묘하게, 자극적 공포 아님), 리스크 등급, 말머리.
   - **부기 질문**: 본문에 나온 갈림길에서 "그때 ~했다면 어땠을까요?" + 열린 의문 1개.
   PD가 "이 소재는 이해 가능한 한 편이 안 된다"고 판단하면 제작하지 않고 '소재조사' 상태를 '보류'로, 메모에 사유를 남긴다. 로그라인은 '소재조사' 메모에 적는다.
   **PD 최종 승인**: 아래 '처음 보는 사람 검수' 결과의 요약과 답이 로그라인과 같은지, 체크포인트가 지켜졌는지, 회수되지 않은 의문이 없는지 확인한다. 통과하지 못하면 고치고 다시 검수한다(최대 2회).
   콘티 설계도 (story.json 쓰기 전, `episodes/<편>/outline.md`에 저장, PD 기획서를 따른다):
   - **중심 질문 1개**: 표지 훅이 던진 "왜?"를 한 문장으로. (예: "왜 음악도 없는데 사람들이 따라 춤췄고, 왜 멈추지 못했나?") 모든 장은 이 질문을 키우거나 답하는 데만 쓴다. 이 질문과 상관없는 흥미로운 사실(예외 규정, 곁가지 수치)은 뺀다.
   - **의문 3단계**: 이상함 ①→②→③이 점점 커지게 (예: 따라 춘다 → 치료할수록 늘어난다 → 기도 하나로 멈춘다). 각 단계는 시간 순서의 사건으로 보여 준다.
   - **답 한 문장 + 구체적 작동 원리**: 추상 용어("집단 심인성 질환")만으로 끝내지 말고, 앞에 나온 장면들이 왜 그렇게 됐는지 하나씩 설명되는 원리로. 가능하면 "원인이었던 것이 해결책이기도 했다" 같은 반전 구조.
   - **복선 1개**: 초반에 '구체적인 물건·말·장면'으로 심고(이름만 툭 던지지 않는다, 독자가 궁금해할 만큼만 보여 준다), 답 장면에서 같은 그림을 재사용해 회수.
   - **시간 순서**: 사건 → 대응 → 결과를 순서대로. 결말 사건(어떻게 끝났나)을 오답 목록 뒤로 빼서 답처럼 보이게 하지 않는다. 답의 재료(배경 사실)를 답 장 전에 미리 설명해 버리지 않는다.
   - **매달린 문장 금지**: "그런데 그중 누군가가—" 같은 미끼는 바로 다음 장에서 회수한다. 부기의 마지막 질문도 본문에서 다룬 내용에서 나와야 한다.
   - **처음 보는 사람 검수**: 콘티를 쓴 뒤, 조사 내용을 모르는 별도 에이전트에게 장별 자막만 주고 ① 이야기 요약 ② 중심 질문 ③ 답 ④ 헷갈린 장을 쓰게 한다. ②·③이 설계도와 다르거나 헷갈린 장이 있으면 고쳐서 다시 검수(최대 2회).
   그다음 `episodes/<ID>-<영문slug>/story.json` 작성 (형식은 기존 편 story.json 참고, 14~17장, 최대 20).
   - 표지 훅: 평범한 설명으로 안 풀리는 디테일 1개 + 사람·숫자, 후보 3개 중 "1초 안에 평범한 답이 떠오르는가"로 걸러 선택. 2장 이후의 답·원인을 표지 글·그림에 쓰지 않는다.
   - 흐름: 발견 장면 → 장마다 사실 1 + 풀리지 않는 질문 1 → 복선 1개(나중에 panel 재사용으로 회수) → 7~10장 '이상한 점' 저장 카드(위 그림 + evidence 3칸) → 오답 목록 → 마지막 2~3장 답 한 방(텍스트 카드: 큰 문장 + → 3줄 + 확정 여부·출처) → 마지막 장에만 부기 "그때 ~했다면 어땠을까요?" + 열린 의문.
   - 문장: 설명문이 아니라 짧은 장면 묘사와 끊어 읽기, 장당 60자 안팎, 자막 2줄 이내. 사실을 지어내지 않는다. C등급은 "~라는 설도 있다"로만.
   - 그림 프롬프트(영문): 장면 하나를 구체적으로, 사람 없으면 "nop": true, 사람은 얼굴 없는 실루엣·멀리서·뒤에서. 피·시신·흉기 금지(빈 방·열린 문 같은 상징). 실존 인물 얼굴 금지. 글자 소품은 "blurred and unreadable".
   - 다루지 않음: 아동 피해, 성범죄, 자살·자해 중심, 재판 중·최근 국내 사건, 범행 수법 상세. 국내 피해자 실명·용의자 암시 금지.
   - caption(첫 줄 훅, 본문 2~3줄, "당신의 가설은? 댓글로 알려주세요.", 출처, 해시태그 2개), threads(반말, 첫 글 훅 + 3~4개 + 마지막 "답은 인스타 @ossak_alarm 에서 확인해 봐."처럼 읽는 사람이 할 행동으로, 글당 500자 이내). 릴스는 아래 '릴스 만들기'.
   - next: 발행계획에서 이 편 바로 다음 날 캐러셀의 표지 훅 (없으면 "다음 편도 내일 밤 9시 30분에 공개됩니다").
4. `python3 ossak/mk.py episodes/<편>` → `python3 ossak/cf.py episodes/<편>` (하루 무료 한도 약 90장, 한 편 20~23장).
   429·한도 초과면 `--model schnell`로 남은 컷을 그리거나 다음 날로 미룬다.
5. 컷 검수: `panels/*.jpg`를 직접 열어 본다(축소 시트로 한 번에). 검은 띠·엉뚱한 사람·얼굴·글자·흉기·구도 불일치는 프롬프트를 고쳐 `--only <id> --force`.
6. `python3 ossak/compose.py episodes/<편>` → `python3 ossak/finish.py episodes/<편> --date <발행일>`
   - 발행일 = 발행계획의 마지막 '인스타 캐러셀' 날짜 + 1일.
   - `preview.jpg`를 열어 자막 겹침·넘침·그림-자막 불일치를 확인하고 고친다.
7. 자동 검수(하나라도 걸리면 발행계획에 넣지 않고 소재조사 상태를 '폐기' 또는 '콘티'로 두고 사유를 메모):
   훅·제목 사실 A/B / 국내 피해자 실명·특정 정보 없음 / 용의자·무죄자 실명·암시 없음 / 피·시신·흉기 직접 묘사 없음 / 실존 인물 닮은 얼굴 없음 / 출처 표기 / 피해자 조롱·가해자 미화 없음.
8. 저장소에 올리기: `git -C <repo> pull --rebase origin main` → `git add ossak/<편> ossak/engine/episodes/<편>/story.json ossak/engine/episodes/<편>/episode.json` → 커밋 → `git push origin HEAD:main`.
   올린 뒤 이미지 주소 하나를 curl로 열어 200인지 확인.
9. 시트: `rows.json` 두 행을 '발행계획' 마지막 행 다음 A:L에 쓴다(M열 이후는 비움). '소재조사' 해당 행 상태를 '완성'으로.
10. **릴스** (아래 '릴스 만들기' 순서대로, 캐러셀 발행 다음 날 12:30).
11. 한두 줄로 보고: 편 ID, 로그라인, 표지 훅, 캐러셀·릴스 발행일, 장수·릴스 길이.

## 릴스 만들기
릴스는 캐러셀을 읽어 주는 영상이 아니다. 팔로워가 아닌 사람이 피드를 넘기다 **귀로 듣고 3초 안에** 계속 볼지 정한다. 목표는 끝까지 보고 프로필로 와서 캐러셀(답)을 보고 팔로우하는 것.
발행: 캐러셀 다음 날 12:30 (프로필에 이미 답이 있도록). 채널 이름 '인스타 릴스', L열 = 영상 주소 + 줄바꿈 + 표지 주소.

1. **릴스 PD 기획** (캐러셀 작가·PD와 다른 에이전트, `episodes/<편>/reel_brief.md`):
   - **목표 감정 한 줄**: 시청자가 끝에 느낄 "그래서 왜?" 하나. 이게 프로필로 보내는 힘이다.
   - **첫 2초 훅**: 첫 문장 15자 안팎, 2초 안에 끝남. 화면 제목(표지 훅)과 같은 이상함. 인사·채널 소개·"오늘은" 금지.
   - **열린 고리 설계**: 3초 안에 "왜?"를 만든다 → 10초 전후 더 큰 이상함 → 중반(20~30초)에 "그런데" 한 번 더 → 마지막에 가장 큰 질문을 이름 붙여 남긴다. 질문형 문장 2개 이상.
   - **귀로 듣는 문장**: 한 문장에 정보 하나, 20자 안팎. 주어·동사 단순하게. 고유명사는 최대 2개, 낯선 용어 금지. 숫자는 문장 하나에 하나. 같은 어미 3번 연속 금지. 쉼표와 "…"로 숨 쉴 자리를 만든다.
   - **장면 설계**: beat 7~10개, 각 3~6초. beat마다 말하는 것을 그대로 보여 주는 컷을 고른다(같은 컷 연속 금지). 첫 beat는 표지 컷, 마지막 beat는 부기 컷.
   - **길이**: 대본 200~260자 (약 35~50초).
   - **엔딩**: 답(원인)은 말하지 않는다. 남은 질문에 이름을 붙여 보낸다. 예: "신발도 없이 숲으로 간 이유… 답은, 프로필을 눌러 확인하세요." 보는 사람이 할 행동으로 말하고, '캐러셀·콘텐츠·업로드·풀버전' 같은 만드는 쪽 말은 쓰지 않는다(캡션·스레드도 같음). 마지막 문장을 첫 문장과 이어지게 쓰면 반복 재생이 자연스럽다(선택).
   - **엔딩은 사건마다 다르게**: 답이 확정된 사건은 "답은, 프로필을 눌러 확인하세요.", 가설뿐인 사건은 "가장 그럴듯한 설명은, …", 신원·이유를 묻는 사건은 "그 이유는, …"처럼. 8편 연속으로 같은 문장이면 틀 티가 난다. 풀리지 않은 사건에 "답은"이라고 약속하지 않는다.
   - **귀로 헷갈리는 말 금지**: 시(도시)/시(詩), 신(신발)/신(神), 시집(책)/시집(결혼), "먼저 간"(떠난/숨진) 같은 말은 풀어 쓴다. 숫자 앞 단위('다섯 고을')는 TTS가 잘못 읽기 쉬우니 받아쓰기로 확인한다.
   - **장소·시대를 한 번은**: 첫 10초 안에 언제·어디인지 한마디("500년 전, 유럽의 한 도시").
   - **곁가지 빼기**: 중심 질문을 키우지 않는 사실(예: 퉁구스카의 유럽 밤하늘)은 캐러셀에만 둔다.
   - **캡션 한 줄(teaser)**: 영상에 없는 디테일 하나로 궁금증을 더한다.
   - 사실·리스크 기준은 캐러셀과 같다. 캐러셀에 없는 새 사실은 넣지 않는다.
   - **호흡 설계 (읽기용 표기 `tts`)**: 자막(say)과 따로, 실제로 읽힐 문장을 beat마다 쓴다. 구글 TTS는 쉼표를 자주 무시하고 엉뚱한 데서 쉰다(예: '숲으로 이어진 / 발자국', '찢고 / 나갔죠').
     - 쉼은 `[pause short]`(약 0.3초)만 쓴다. `[pause]`·`[pause long]`은 쓰지 않는다 — 구글 목소리가 '음,' 같은 군소리를 넣는다. 쉼은 문장당 최대 1개, beat당 2개.
     - 쉬는 곳: 절과 절 사이(-고/-는데/-자/-니 뒤), 8자 넘는 긴 주어·주제어 뒤, 긴장 직전("…텅 비어 있었습니다" 앞), 정보와 질문 사이, 엔딩 안내("답은…") 앞.
     - 쉬지 않는 곳: 짧은 주어·주제어(5자 이하: '몇몇은', '신발도') 뒤, 꾸미는 말과 꾸밈 받는 말 사이('이어진 발자국'), 부사와 동사 사이, 숫자와 단위 사이, '왜·그런데' 같은 짧은 말 뒤.
     - 쉬지 않을 곳의 쉼표는 tts에서 지운다. 열거('신발도 식량도')는 쉼표 없이 한 호흡. 말줄임표(…)는 tts에서 `[pause short]`로 바꾼다.
     - 첫 beat(훅)는 쉼 없이 한 호흡에 2초 안으로.
     - 만든 뒤 `python3 ossak/breath.py episodes/<편>`으로 호흡 지도를 본다. reel.py는 엉뚱한 쉼·빠진 쉼이 있으면 속도를 살짝 바꿔 최대 3번 다시 만들고 가장 나은 것을 쓴다. 그래도 남으면 tts 문장을 고친다(어순 바꾸기, 쉼 위치 옮기기).
2. 원고에 넣기: story.json(디아틀로프는 episode.json)에 `"reel": {"beats": [{"say": "…", "panel": "s02a"}], "teaser": "…"}`. 자막은 say와 같고, 달라야 할 때만 `"sub"`.
3. **처음 듣는 사람 검수**: 사건을 모르는 별도 에이전트에게 beat를 '초 단위 시간과 함께' 순서대로 주고 ① 2초 뒤 계속 볼지 ② 넘겼을 beat와 이유 ③ 끝나고 남는 질문 ④ 프로필에 가 볼지 ⑤ 귀로 듣기 어려운 문장을 묻는다. 릴스 PD가 기획서와 비교해 고친다(최대 2회).
4. `python3 ossak/reel.py episodes/<편> --date <캐러셀 다음 날>` → `ossak/<편>/reel.mp4`, `reel_cover.jpg`, `episodes/<편>/reel_preview.jpg`, `reel_row.json`.
   - 목소리: '설정' B17 '구글 TTS 키'가 있으면 `GOOGLE_TTS_KEY`로 넘겨 구글 TTS, 없으면 Cloudflare MeloTTS(무료).
   - reel_preview.jpg를 열어 제목·그림·자막 겹침을 보고, Cloudflare Whisper(`@cf/openai/whisper-large-v3-turbo`)로 음성을 받아써 잘못 읽은 말이 없는지 확인한다. 잘못 읽으면 say를 소리 나는 대로 고치고 sub에 원래 표기.
5. 올리기: `git add ossak/<편>/reel.mp4 ossak/<편>/reel_cover.jpg` + 원고 → 커밋·푸시 → 주소 200 확인 → `reel_row.json`을 발행계획 마지막 행 다음 A:L에.
