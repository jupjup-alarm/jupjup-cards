## 구성
- `ossak/short.py` **쇼츠 엔진** — 세로 그림 생성(`--images`) + 내레이션 + 단어 자막 → `ossak/<편>/<편>.mp4`, `<편>_thumb.jpg`, `episodes/<편>/short_preview.jpg`, `short_rows.json`
- `ossak/reel.py` 목소리(구글 TTS)·호흡 재시도 함수 (short.py가 가져다 씀). 예고편 릴스 렌더러는 더 쓰지 않는다.
- `ossak/timing.py` 무음 위치 ↔ 원고 글자 맞추기: 단어 자막 시각과 호흡 검사(`python3 ossak/timing.py episodes/<편>`). API를 쓰지 않는다.
- `ossak/breath.py` 받아쓰기(Cloudflare Whisper)로 보는 호흡 지도 — 오독 확인용 (`--short`)
- `ossak/scout.py` **소재 조사 (API 크레딧)** — 터진 쇼츠 목록 → 후보 고르기(Opus+웹) → 반응 증명(proven.py) → 후보마다 원문 조사(Opus+web_fetch, 동시에) → 사전 검수(Sonnet, 따로) → 점수 → `rows.json`(소재조사·조사노트에 넣을 행). 아래 '소재 조사 (API 크레딧 우선)'.
- `ossak/proven.py` 반응 증명(유튜브 공개 수치), `ossak/clip.py` 실물 증거(옛 신문 지면 자르기)
- `ossak/cf.py` Cloudflare Workers AI 키 읽기·호출 도구. 세로 그림 크기(864×1536)는 short.py가 정한다.
- `ossak/mk.py`·`compose.py`·`finish.py`·`captions.py` 옛 캐러셀 도구(보관). 옛 절차는 `README_carousel.md`.
- `fonts/` 고운바탕·개구·Noto Sans KR(OFL), `refs/boogi_sheet.png` 부기 캐릭터 시트(로고·끝 장면 참고 이미지)
- `episodes/<ID>-<slug>/` short.json·short_brief.md (그림·음성은 커밋하지 않음)

## 소재 조사 (API 크레딧 우선, 2026-11-05 사용자 결정)
"소재 조사도 API 우선 → 크레딧 다 쓰면 주간 한도(구독) 사용으로 전환. API를 쓸 때 캐시를 써라 — 효도알람처럼."
- 예약 작업 '오싹알람 소재 조사'(매일 05:47)는 구독 주간 한도(Claude·Claude Code 공용)를 쓴다. 토큰을 많이 먹는 후보 고르기·원문 조사·사전 검수는 `ossak/scout.py`가 **콘솔 API 크레딧**으로 돌리고, 예약 작업은 시트 읽기·쓰기와 결과 JSON 확인만 한다.
- API 모듈은 효도알람 `hyodo/engine/lib/llm.py`를 그대로 쓴다: **배치(Message Batches, 요금 50%)가 기본**, `HYODO_BATCH_WAIT`분(기본 45) 안에 안 끝나면 바로(정가) 부름 · **프롬프트 캐시** — 모든 단계가 같은 규칙(scout.py `RULES`)을 시스템 프롬프트로 써서 두 번째 호출부터 캐시 읽기(0.1배), 웹 도구 반복 중에도 앞부분은 캐시(2026-11-05 확인: 규칙 1,496토큰 쓰기 → 다음 호출 캐시 읽기, 비용 1/10) · web_fetch 12,000토큰 상한 · 사용량·추정 비용 `<out>/llm_usage.jsonl`.
- 실행: `python3 ossak/proven.py --scan --global --min 200000 --json > scan.json` → `python3 ossak/scout.py --brief brief.md --out <폴더> --n 3 --scan scan.json` (백그라운드로 — 배치를 기다려 몇 분~1시간). 메모(brief) = '지침로그' 최근 행, '소재조사' 기존 사건명 전부, '조사중' 개수, '유튜브' 최근 14편 제목, 제보, 다음 ID(말머리별 마지막 번호 + 1).
- 종료 코드 **3 = API 크레딧 부족·키 없음** → 예약 작업은 예전 방식(하위 에이전트로 사전 검수, 직접 웹 조사 — 구독 사용량)으로 이어 가고 보고 맨 위에 "API 크레딧 부족 — 구독 사용량으로 조사(콘솔에서 충전 필요)".
- 점수·통과 기준은 예전 소재 조사 규칙 그대로(반응 증명 30 · 사전검수 25 · 사람·행동 10 · 끝 단서 10 · 사실 10 · 우리 각도 5 · 리스크 10, 70점 미만 버림, 30만+ 소재는 결 4점이면 통과). 2026-11-04 구성·편집 규칙에 맞춰 0초 장면·당시 실제 오답·실물 증거 찾을 곳도 조사해 메모(K열)에 남긴다.

2. **고르기**
   - **아래 '제작 순서' 표를 먼저 본다.** 위에서부터 아직 short.json이 없는(또는 그림·영상이 없는) 편을 만든다. 서사형은 하루 최대 2편(그림 한도), 루프형 1편. 옛 캐러셀 편은 사실을 그 편 story.json(디아틀로프는 episode.json)·조사노트 안에서만 쓴다.
   - ⭐ **반응이 증명된 소재 우선** (2026-11-03 사용자 결정 — "이미 반응이 증명된 소재를 우리 스타일로 만드는 게 성공 방정식"): 소재조사 M열 점수보다 **'반응 증명'**(N열 점수 근거의 `증명: 최고 N회`)이 큰 소재를 먼저 고른다. 같은 사건을 다룬 국내 또는 해외 쇼츠가 30만 회 이상이면 최우선, 둘 다 5만 회 미만이면 뒤로. 확인: `python3 ossak/proven.py --topic "한글 사건명" "영문 사건명" --global`(국내·해외 둘 다, 키 GOOGLE_TTS_KEY). 해외에서만 터진 소재는 국내에 아직 없는 기회로 본다. 남의 대본·구성·그림·창작 괴담은 가져오지 않는다 — 실제 기록 사건만, 원문으로 다시 조사해 우리 훅(권위·일상×초자연 충돌, 기록이라는 증거)·구성·끝 단서로 만든다. 남의 영상과 첫 문장·제목 틀이 같으면 안 된다(PD가 그 영상 제목을 보고 다르게 쓴다).
     - **소재의 결대로 판단한다** (2026-11-03 사용자 결정 — "무서움으로만 판단하지 말고 소재에 맞게. 기묘한 거면 기묘하게, 신기한 거면 신기하게. 터졌다는 건 가능성이 높다는 거고, 우리 스타일로 잘 다듬으면 된다"): short.json `mood`를 소재에 맞게 정한다 — `horror`(공포: 귀신·흉가·금기), `mystery`(기묘: 실종·설명 안 되는 디테일), `wonder`(신기: '와, 진짜?' 싶은 기록·현상, 예: 조선왕조실록 속 하늘의 빛). 검수 점수도 그 결의 축으로 잰다(공포=무서움, 기묘=기묘함, 신기=신기함·놀라움). 국내·해외 쇼츠에서 이미 터진 소재(같은 사건 최고 조회 30만+)는 그 축 4점이면 통과. 검수 질문에 "이 소재로 이미 터진 영상 제목"을 함께 주고 "그보다 우리 첫 1초가 더 궁금한가"를 묻는다. 신기형도 연출은 우리 채널 톤(밤, 차분한 내레이션, 기록이라는 증거, 끝 단서 질문) 그대로.
   - **새 서사형**: 제작 순서 표가 다 끝났을 때. '소재조사' 상태 '조사중' 중 조사노트 사실이 충분하고 훅·핵심 사실이 A/B인 것 가운데 점수가 가장 높은 것.

   - 소재 비중: 공포형 기록 50% · 기묘한 실화·실종 40% · 기묘한 사실(루프형 전용) 10%. 말머리는 세계기담·새벽괴담·미제파일·그날의 기록·그 후를 그대로 쓴다.
   - 구성 유형 7가지(A 빈 현장형, B 목격담 조각형, C 단서 추적형, D 확산형, E 한순간 해부형, G 기록 괴담형, L 루프형)를 돌려 쓰고, 같은 유형을 이틀 연속 쓰지 않는다.
   - '지침로그' 최근 행의 방향을 반영한다.
   - ⭐ **터진 영상 스타일 반영** (2026-11-04 사용자 결정 — 같은 사건으로 터진 영상 10개 비교: 짧고, 첫 화면에 사건이 보이고, 반응·웃음 댓글이 달리고, 답을 줌. 우리 영상은 편당 650~1,500회에 머묾):
     1. **첫 화면 = 사건 그 자체.** 분위기 컷(빈 계단·실루엣·어두운 집)으로 시작하지 않는다. '이상한 것'(떨어지는 고기 조각, 초록빛 아이 둘, 계단 위 흐릿한 형체, 마당에서 뜬 빛)을 첫 그림 가운데에 **밝고 크게, 선명하게** 그린다(`"bright": true`). 피·시신 금지.
     2. **사람들의 반응을 넣는다.** 신기·기묘형은 당시 사람들의 반응 한 줄을 넣는다(예: "그런데 이웃 두 명이… 그걸 맛봤습니다."). 존댓말·차분한 톤은 유지(가볍게 웃기지는 않는다).
     3. **답이 있는 소재는 답을 준다.** 가장 유력한 설명까지 말해 만족감을 준다(예: 고기비 → "범인은 독수리 떼. 먹은 걸 한꺼번에 게워 낸 겁니다."). 마지막 질문은 숨긴 답이 아니라 **반응·의견**을 묻는다("당신이라면, 먹어 봤을까요?"). 답 없이 열어두는 끝(단서 질문)은 정말 답이 없는 소재(레이넘 홀 같은)와 공포형에만.

- **소재**: '기록으로 남은 섬뜩한 이야기'. 사실 등급은 "그렇게 기록됐다"가 A다.
  - 조선왕조실록·한국고전종합DB의 괴이 기록, 『어우야담』·『용재총화』 같은 고전 야담(원문 공개)
  - 오래된 신문의 괴담 보도(네이버 뉴스라이브러리, Chronicling America), 공식 조사 기록이 있는 '귀신 들린 집'·폐허, 유명한 심령 사진·녹음 사건
  - 오래된 해외 민속 기록
- **금지는 그대로**: 피·시신·흉기 묘사, 실제 살인 사건을 괴담으로 소비하기, 아동 피해, 자살·자해, 최근 국내 사건, 실존 피해자 조롱. 점프스케어(갑자기 큰 소리·얼굴)도 쓰지 않는다.
  - 무서움은 피가 아니라 소리·빈자리·반복·'있으면 안 되는 것'에서 나온다.
- **이야기 방식**
  - 답(과학적 설명)으로 안심시키며 끝내지 않는다. 설명이 있으면 짧게 "이런 설명도 있습니다"로 두고, 마지막은 설명되지 않는 디테일 하나로 닫는다.
  - 감각 묘사: 들리는 것(발소리·두드림·이름 부르는 소리), 보이는 것(문틈·창 너머·사진 구석), 반복되는 것(매일 같은 시각).
  - 시점은 "그 방에 있었다면"처럼 보는 사람을 현장에 세운다. 단 기록에 있는 것만 장면으로 만든다.
  - 장면마다 정보 하나 + 불안 하나. '그런데'로 한 단계씩 다가가고, 가장 무서운 디테일은 끝 20% 직전(`sfx: hit`).
- **그림**: 더 어둡게, 빛은 하나(촛불·창빛·손전등). 인물은 멀리서 뒷모습. '무언가'는 직접 그리지 않고 문틈의 어둠, 비어 있는 의자, 흐릿한 형체로. (`"mood": "horror"`면 엔진이 프롬프트에 어두운 조명 문구를 붙이고 그림을 조금 더 어둡게 한다.)
- **소리**: `"mood": "horror"`면 내레이션 0.95배, 바람 소리가 조금 크고 낮은 울림이 깔리고, hit 앞에 긴장음이 차오른다. 장면별 `"sfx"`: `"knock"`(말 시작 전 둔탁한 두드림 세 번 — 두드림·던짐·발소리 기록에), `"heartbeat"`(장면 내내 낮은 심장 소리 — 가장 긴장되는 장면 하나), `"hit"`. 여러 개면 `["knock", "hit"]`. 기록에 소리가 있는 장면에만 쓴다.
- **화면**: 공포형은 색을 35% 빼고 차갑게, 필름 입자와 촛불 같은 약한 깜빡임이 들어간다(엔진 자동).

## 호흡 설계 (읽기용 표기 `tts`)
- **엔진이 자동으로 하는 것** (2026-10-27 피드백 "쉬어야 할 때 쉬지 않고 이어 말해 문맥이 이상하다"): 구글 목소리는 쉼표를 자주 무시한다. 그래서 short.py가 tts의 쉼표·말줄임표를 모두 `[pause short]`로 바꾸고, 문단 안 장면과 장면 사이에도 `[pause short]`를 넣는다. → **tts의 쉼표는 '여기서 숨 쉰다'는 뜻이다.** 숨 쉬지 않을 곳에는 쉼표를 쓰지 않는다(자막 say에는 쉼표가 있어도 된다).
자막(say/sub)과 따로, 실제로 읽힐 문장을 장면마다 쓴다. 구글 TTS는 쉼표를 자주 무시하고 엉뚱한 데서 쉰다(예: '숲으로 이어진 / 발자국', '찢고 / 나갔죠').
- 쉼은 `[pause short]`(약 0.3초)만 쓴다. `[pause]`·`[pause long]`은 쓰지 않는다 — '음,' 같은 군소리가 들어간다. 쉼은 문장당 최대 1개, 장면당 2개.
- 쉬는 곳: 절과 절 사이(-고/-는데/-자/-니 뒤), 8자 넘는 긴 주어·주제어 뒤, 긴장 직전("…텅 비어 있었습니다" 앞), 정보와 질문 사이.
- 쉬지 않는 곳: 짧은 주어·주제어(5자 이하) 뒤, 꾸미는 말과 꾸밈 받는 말 사이('이어진 발자국'), 부사와 동사 사이, 숫자와 단위 사이, '왜·그런데' 같은 짧은 말 뒤.
- 쉬지 않을 곳의 쉼표는 tts에서 지운다. 열거('신발도 식량도')는 쉼표 없이 한 호흡에, 끝에 `[pause short]` 하나. 말줄임표(…)는 tts에서 `[pause short]`로.
- 첫 장면(훅)은 쉼 없이 한 호흡에 3초 안으로.
- 숫자는 tts에서 한글로('아홉 명', '천구백오십구 년', '오월'). 자막(sub)은 숫자로('9명').
- short.py는 엉뚱한 쉼·빠진 쉼이 있으면 속도를 살짝 바꿔 최대 3번 다시 만들고 가장 나은 것을 쓴다. 그래도 남으면 tts 문장을 고친다(어순 바꾸기, 쉼 위치 옮기기).

## 화면·소리 (엔진이 자동으로 하는 것)
- 1080×1920 전체를 세로 그림으로 채우고 그림마다 천천히 확대·이동(`move`). 그림이 바뀔 때 하드 컷 + 첫 4프레임 살짝 펀치 + 작은 '휙'(같은 그림 안에서는 끊지 않음). `proof` 컷은 흐린 배경 위 원본 카드 + 형광펜 + credit. `big`은 가운데(y≈820) 큰 글자가 '톡'과 함께 튀어나옴. `src_line`은 아래(y≈1468) 작은 고정 글자. `sfx: hit` 장면은 화면이 살짝 어두워졌다가 바뀐다.
- 화면 위(y≈318)에 훅 제목 2줄이 처음부터 끝까지 고정. 오른쪽 위에 부기+오싹알람 작은 로고.
- 자막은 실제 음성의 쉼 위치에 맞춘 어절 시각(timing.py)으로 2~3어절씩, 말보다 0.06초 먼저, 가운데 아래(y≈1130). `emph`·`accent_word` 단어는 말머리 색. 위 300px·아래 420px·오른쪽 140px에는 글자를 두지 않는다.
- 소리: 내레이션(구글 Umbriel, 사용자 선택) + 끝까지 깔리는 바람·낮은 화음(바닥 약 -34dB, 무음 구간 0) + 그림 전환 '휙'·큰 글자 '톡'·증거 '종이' + 장면 sfx(thud·knock·heartbeat·hit). 끝은 마지막 말 0.35초 뒤.
- 첫 프레임 = `<편>_thumb.jpg`(제목 + 첫 그림 + 첫 자막). 유튜브 썸네일로도 쓴다.
