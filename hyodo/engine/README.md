## 3. video.json
- 장면 9종 순서: hook → summary → official → check → table → calc → apply → kids(반대 세대 혜택 1개) → outro.
- 필드: id, category(본인/자녀/정책변화), checked, title, thumb{big, age, sub}, voice(ko-KR-Chirp3-HD-Sulafat 고정), tags[](유튜브 태그 5~8개, 정책명·대상·줄임말), hashtags[](설명란 끝 2~3개), playlist(본인 받을 돈/자녀 받을 돈/달라지는 정책), sources[{name,url}], scenes[{id, type, chapter, data, say[]}], shorts[{id, title, scenes[]}]. 예시: episodes/S-0001-youth-future/video.json.
- data-at 규칙: 화면 요소는 say의 k번째 문장이 시작될 때 나타난다. 기본은 행 i → 문장 i+1. 다르면 data에 at, note_at, note2_at, banks_at, tip_at, tel_at을 적는다.
- 숫자 계산(calc)은 코드가 한다. 대본에 쓰는 계산값은 직접 검산한다.
- 숫자를 화면과 다르게 읽어야 하면 `{표시|읽기}`로 적는다: `{1397|일삼구칠}번`, `{6%|6퍼센트}`, `{1,800만|천팔백만} 원`. 자막에는 앞, 내레이션은 뒤.
- 쉼 표기(아래 '내레이션 쉼' 참고): 숨 쉴 자리에 ` / `. 문장 끝(. ? !)은 자동으로 문장 쉼.
- 오프닝 "오늘도 받을 돈부터 챙겨드릴게요", 엔딩 "자녀분께도(부모님께도) 이 영상 꼭 보내주세요".

## 4. 문장 규칙 (번역투 금지)
화면 글자·제목·썸네일·내레이션·설명란·시트의 표지 훅까지 60대가 일상에서 실제로 하는 말로 쓴다. 짧은 문구일수록 어색해지기 쉬우니 소리 내어 읽어 본다.
- 생활 동사: 계좌를 '만들다(개설하다)', '신청하다'. '계좌를 열다', '진행하다' 남용 금지.
- 짧은 문구도 말로 끝낸다: "계좌 안 열면 가입 끝"(X) → "이 날짜 지나면 가입 못 해요"(O). 명사로 뚝 끊지 않는다.
- 뜻이 두 가지인 말 금지: '끝', '완료', '마감'처럼 누가 끝내는지 불분명한 말 → '못 해요', '끝나요', '받을 수 없어요'.
- 번역투·행정투 금지: ~에 대해, ~를 통해, ~으로 인해, ~하는 것이 가능, ~되어지다, ~하게 됩니다, 사물 주어 피동문("지급이 이루어집니다" → "매달 25일에 들어와요").
- 제도 용어는 사람 말로 풀어 쓴다: 기여금 매칭 → 정부가 보태는 돈, 소득인정액 → 소득과 재산을 합친 금액(처음 한 번은 용어도 같이).
- 영어식으로 머릿속에서 압축하지 말고, 자연스러운 한 문장을 먼저 쓴 다음 줄인다. 줄일 때도 '~해요/~못 해요' 같은 끝말은 남긴다.

## 4-1. 내레이션 쉼 (tts.py가 표기대로 정확히 쉰다)
TTS는 쉼표에서 쉬기도 하고 안 쉬기도 하며, 구절 중간에 엉뚱하게 쉬기도 한다. 그래서 쉼은 대본에 직접 표기하고, 표기가 없는 곳은 이어 말하게 만든다.
- ` / ` 자리에서 구절을 나눠 따로 읽고 0.25초 쉰다. 문장 사이 0.45초, '누가.'처럼 짧은 이름표 뒤 0.3초, 줄(say 항목) 사이 0.55초.
- 구절 안에서 TTS가 스스로 낸 0.15초 넘는 쉼은 0.12초로 줄인다(이어 말하기). 클립 앞뒤 무음은 잘라 낸다.
- `/`를 넣는 곳: 문장 앞 짧은 말 뒤(다만 / 참고로 / 그다음 / 첫째,), 조건·이유 절 끝(-면, / -다면, / -니, / -는데), 나열 사이(가입 신청, / 가입 심사, / 그리고 계좌 개설), 긴 주어·주제어 뒤(보도자료에는 정해진 기간이 지나면 /).
- `/`를 넣지 않는 곳: 날짜·기간(11월 16일 월요일부터 27일 금요일까지), 숫자와 단위, 꾸미는 말과 명사, 본용언과 보조용언, 기관명과 전화번호 사이의 짧은 묶음. 한 구절은 자막 두 줄(32자)을 넘지 않게.
- 쉼표로 끝나는 구절은 문장 끝처럼 떨어지지 않고 이어지는 억양으로 읽힌다(음높이로 확인함). 그래서 `/` 앞 구절은 되도록 쉼표나 연결어미로 끝낸다. 구절을 너무 잘게(5자 미만) 나누지 않는다.
- Chirp3의 [pause] 마크업은 길이가 매번 달라 쓰지 않는다.

## 4-2. 자막 (넷플릭스 한국어 자막 가이드, lib/subs.py)
- 한 줄 16자(숏츠는 큰 글자를 위해 13자)(한글 1, 영문·숫자·공백·부호 0.5), 최대 2줄, 한 줄에 들어가면 한 줄. 아랫줄이 긴 피라미드를 우선.
- 줄 끝에 마침표·쉼표 없음. 한 자막에 두 문장이면 쉼표로 잇는다('누가, 10월에…').
- 줄바꿈 금지 자리(형태소 분석으로 판정): 꾸미는 말|명사, 본용언|보조용언(보태 줍니다), 부정어|동사(못 해요), 숫자|단위·날짜 묶음, 의존명사 앞(할 수, 우체국 등), 명사|명사 묶음.
- 자막 단위는 내레이션 구절에 맞춰 시작·끝이 소리와 정확히 맞는다. 5/6초~7초, 다음 자막과 12프레임 안이면 2프레임 간격으로 붙이고, 장면 경계는 넘지 않는다. 초당 12자 이하.
- 모양: 흰 글자 + 검은 테두리·그림자, 상자 없음(줄마다 상자가 겹치는 문제 없음). 시니어용 크기: 롱폼 80px, 숏츠 76px.
- 빌드 후 `out/<tag>/subs_check.json`이 비어 있어야 한다(줄 길이·길이·속도 위반 목록). 줄바꿈이 어색하면 say의 `/` 위치나 문장을 고친다.

## 4-3. 화면 글자 크기 (시니어 기준, lib/scenes.py)
- 롱폼(1920×1080): 제목 80px, 본문 52~62px, 보조 글자 44px 이상, 출처·확인일 36px, 강조 숫자 200px 이상.
- 숏츠(1080×1920): 제목 76px, 본문 48~54px, 보조 42px 이상.
- 화면 글자는 자막 자리 위에서 끝나야 한다: 롱폼 y≤830, 숏츠 y≤1270.
- 자동 맞춤: 한 줄로 보여야 하는 문구(data-fit)는 폭에 맞게 줄이고, 자막 자리를 넘는 덩어리는 최소 0.8배까지 줄인다. 줄인 비율은 body의 data-fitted에 남는다. 0.9보다 작게 줄었으면 화면 문구를 짧게 고친다(글자가 다시 작아지므로).
- 화면 문구는 짧게: 표 한 칸·체크 문항·취급기관 목록이 길어지면 크기가 줄어든다. 자세한 내용은 내레이션과 설명란으로 보낸다.

## 5. 검수 (각각 별도 하위 에이전트, 대본을 쓴 맥락과 공유하지 않음)
1. 팩트체크: video.json의 모든 숫자·날짜·요일·조건·기관·전화번호를 원문 URL을 직접 열어 대조. 판정 통과/반려 + 고칠 문장. 반려면 고쳐서 한 번 더 받고, 두 번째도 반려면 유튜브 탭 상태 '보류'.
2. 문장 검수: 위 문장 규칙과 쉼 표기(4-1)로 모든 화면 문구와 say를 한 줄씩 판정. 사실 의미는 바꾸지 않는다.
3. 시각 검수: 렌더 전 `hyperframes snapshot --at <장면 끝-0.5초> --no-end`로 장면별 마지막 화면을 찍어 시트로 모아 직접 본다. 확인: 글자 줄바꿈·넘침, 자막 자리(롱폼 y>830, 숏츠 y>1270)를 침범하는지, 자동 축소(data-fitted)가 0.9 미만인지, 캐릭터와 글자 겹침, 공식 캡처의 강조 박스가 보이는지.

## 6. 제작
- 공식 캡처: `node lib/capture.cjs <보도자료 URL> "<강조할 글자>" episodes/<편>/official.png` (강조 박스가 화면 중앙에 오도록 스크롤). 클라우드에서 정부 사이트가 막히면 정책브리핑(korea.kr) 같은 다른 공식 페이지로 바꾸고, 그래도 안 되면 official 장면을 빼지 말고 보고에 적는다.
- 빌드: `HYPERFRAMES_SKIP_SKILLS=1 python3 -I lib/build.py episodes/<편> --fmt both --jobs 2`
  - TTS(구절별 캐시, 쉼 표기대로 이어 붙임) → timeline.json(줄·구절 시각) → 장면 HTML(바뀐 장면만 다시 씀) → hyperframes 렌더(바뀐 장면만) → 내레이션·배경음(말할 때 자동 감쇄)·효과음(장면 전환 휙, 체크 딩) 합성, -14 LUFS → 자막(ASS, 넷플릭스 규칙, 구절 시각에 맞춤) 굽기 → H.264.
  - 렌더는 화면 캡처 방식이라 영상 1초에 약 3초. 5분 롱폼 + 숏츠 2편 ≈ 20분, 10분 롱폼 ≈ 35분.
- 썸네일: `python3 lib/thumb.py episodes/<편>` → 1280×720, 큰 숫자 + 대상 배지 + 노란 띠 한 줄 + 막내(point).
- 업로드 정보: `python3 lib/meta.py episodes/<편>` → upload.json(제목·설명·챕터·태그·고정 댓글, 숏츠 2편). 태그·해시태그는 편 주제에 맞게 meta.py를 쓰기 전에 video.json `tags`에 적는다(없으면 meta.py 기본값 — 청년미래적금용이라 반드시 고친다).
- 공개: `python3 lib/publish.py episodes/<편>` → `hyodo/<ID>/` + upload.json의 video_url·thumb_url.
- 시트 행: `python3 lib/rows.py episodes/<편> <롱폼 업로드일> "<검수 결과>"` → out/sheet_rows.json(유튜브 탭 A~P 3행).
- 막내 캐릭터 새 포즈가 필요하면 `lib/char.py`의 BASE 문구 + base.png를 참고 이미지로 넣어 생성하고 `lib/cutout.py`로 배경을 지운다. 생성 결과는 눈으로 확인한다(포즈가 프롬프트와 다르게 나오는 경우가 있음).

## 7. 마무리
- 결과 검사: ffprobe로 길이·해상도, `ffmpeg -af ebur128`로 음량(-14 LUFS 근처), 완성본(자막 구운 것)에서 장면마다 한 장씩, 그리고 두 줄 자막이 뜬 순간을 원본 크기로 잘라 직접 본다. 숏츠도 4장씩.
  - 쉼 검사: 각 줄 wav에서 silencedetect(-45dB, 0.18초)로 찾은 쉼이 구절 경계(segs)와 모두 일치해야 한다(예상 밖 쉼 0).
  - 자막만 고쳤을 때는 다시 빌드해도 장면 렌더는 건너뛰고 합성·자막·인코딩만 돈다(약 1분).
- 커밋: `git pull --rebase origin main && git add hyodo && git commit -m "hyodo: <ID>" && git push origin HEAD:main` (거절되면 pull --rebase 후 최대 5번). 푸시가 끝나야 공개 주소가 열린다 — `curl -sI <video_url>`이 200인지 확인.
- 유튜브 탭에 롱폼 1행 + 숏츠 2행: 업로드일(롱폼 월·수·금 07:00, 숏츠 다음 날·다다음 날 12:30), 제목, 설명, 태그, 고정 댓글, 챕터, L 영상 주소(video_url), M 썸네일 주소(롱폼만), N 재생목록, O 상태 '검수'(사용자가 확인 후 '업로드대기'로 바꾼다 — 자동 승인으로 바꾸라는 사용자 결정이 있기 전까지), P 검수 결과("팩트체크 통과 · 문장 검수 N건 반영 · 시각 검수 통과 · 자막 위반 0 · -14 LUFS"처럼 — '통과'가 있어야 ego lite가 올린다. 걸린 게 있으면 '통과'를 쓰지 말고 이유).
- 소재조사 상태를 '완성'으로, 조사노트 출처를 원문으로 갱신.
- 업로드는 ego lite가 youtube/upload.mjs(오싹알람 복제, 효도알람 채널 ID 확인)로 한다. 리스크 중·고 편은 '보류'로 두고 알린다.
- 사용자에게는 롱폼·썸네일·숏츠 파일과 한두 문장 요약만 보낸다.
